---
title: 技术架构
---

NookMux 由 Go 后端、React 管理后台和多种持久化/缓存组件组成。

```text
客户端 / SDK / 控制台
        │
        ▼
Gin 路由层（router）
        │
        ├─ 管理 API：controller → service → model(GORM)
        │
        └─ AI 中继：middleware → relay → 上游渠道适配器
                                │
                                ├─ OpenAI / Azure / Anthropic / Gemini
                                ├─ OpenRouter / DeepSeek / Moonshot / 智谱
                                ├─ AWS / Vertex / MiniMax / Ollama / SiliconFlow
                                └─ ByteDance / Xiaomi / 自定义渠道
```

## 后端分层

- `internal/httpapi/router/`：挂载 API、relay、dashboard、静态资源和调试路由。
- `internal/httpapi/controller/`：HTTP 边界、请求校验、响应组织和管理操作审计埋点，按资源拆子包（channel、user、token、billing、relay 等）。
- `internal/httpapi/middleware/`：认证、限速、请求体恢复、分发和安全校验。
- `internal/domain/`：领域服务：计费（billing）、渠道选择与自动禁用（channel）、审计（audit）、排行榜、工单、敏感词匹配、分组倍率。
- `internal/store/`：GORM 模型、迁移、缓存和数据库访问（按资源子包组织），需兼容 SQLite / MySQL / PostgreSQL。
- `internal/infra/`：基础设施：数据库/Redis 客户端、磁盘缓存与请求体存储、邮件、安全（SSRF/IP/哈希/TOTP）、运行时监控与 goroutine 池、日志、HTTP 传输层与 SSRF 防护、媒体解码、token 计数、通知、支付集成、Passkey、定制语音。
- `internal/config/`：系统、运营、模型、计费、审计和性能配置。
- `internal/relay/`：AI 请求中继、协议转换、供应商适配、usage 统计和计费保护。
- `internal/httpapi/`（根包）：gin 边界工具（`ApiError*` 响应族、请求体读取、上下文键助手）。
- `internal/common/`：业务全局变量与零碎工具内核（全局开关、`ContextKey` 注册表、`SysLog`、环境变量读取、字符串工具等）。

## 前端架构

- `web/src/routes/`：TanStack Router 文件路由。
- `web/src/features/`：按功能拆分页面、API、组件、hooks 和类型。
- `web/src/components/`：通用 UI、布局、数据表格和基础组件。
- `web/src/i18n/`：中英文前端文案。

## 数据与缓存

- 主数据库默认 SQLite，也支持 MySQL 和 PostgreSQL。
- Redis 可用于缓存和多节点协同。
- 日志数据库可通过 `LOG_SQL_DSN` 单独配置。
- 多模态资源、请求体磁盘缓存和性能监控通过环境变量及系统设置控制。
