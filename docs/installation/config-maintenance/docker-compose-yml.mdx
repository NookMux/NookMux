---
title: Docker Compose Configuration Guide
---

This document explains the structure of NookMux's current `docker-compose.yml` file and common extension patterns. The root configuration in the repository is the source of truth: it starts NookMux and Redis by default and does not include MySQL/PostgreSQL services. If you need an external database, set `SQL_DSN`.

## Recommended Current Configuration

```yaml
services:
  nookmux:
    image: ghcr.io/nookmux/nookmux:latest
    container_name: nookmux
    restart: always
    command: --log-dir /app/logs
    ports:
      - "3000:3000"
    volumes:
      - ./data:/data
      - ./logs:/app/logs
    environment:
      - REDIS_CONN_STRING=redis://:change_this_password@redis:6379
      - TZ=Asia/Shanghai
      - ERROR_LOG_ENABLED=true
      - BATCH_UPDATE_ENABLED=true
      - SESSION_SECRET=replace_with_a_random_string
      - CRYPTO_SECRET=replace_with_another_random_string
    depends_on:
      redis:
        condition: service_healthy

  redis:
    image: redis:latest
    container_name: redis
    restart: always
    command: ["redis-server", "--requirepass", "change_this_password"]
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "change_this_password", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5
```

<Card type="warning" title="Do not use the sample passwords directly">
  The sample values `change_this_password` and `replace_with_a_random_string` must be replaced with production-only random values.
</Card>

## NookMux Service Fields

| Parameter | Description |
| --- | --- |
| `image` | Official image, currently `ghcr.io/nookmux/nookmux:latest`. |
| `container_name` | Container name, with `nookmux` used in the example. |
| `command` | Startup arguments. `--log-dir /app/logs` points logs to a persistent path. |
| `ports` | Port mapping, default `3000:3000`. |
| `volumes` | Data and log persistence. At minimum, mount `/data`. |
| `environment` | Environment variable settings, see the [Environment Variables Configuration Guide](/installation/config-maintenance/environment-variables). |
| `depends_on` | Waits for Redis to become healthy before starting the app. |
| `healthcheck` | Optional health check that verifies `/api/status` returns success. |

## Database Configuration

### Default SQLite

If `SQL_DSN` is not set, SQLite is used and the database path defaults to `/data/one-api.db`. This is suitable for personal or small-scale deployments.

### External MySQL

```yaml
environment:
  - SQL_DSN=mysql://user:password@mysql-host:3306/nookmux
```

### External PostgreSQL

```yaml
environment:
  - SQL_DSN=postgres://user:password@postgres-host:5432/nookmux
```

The NookMux backend must remain compatible with SQLite, MySQL, and PostgreSQL. Make sure the database character set and permissions meet production requirements.

## Redis Configuration

```yaml
environment:
  - REDIS_CONN_STRING=redis://:password@redis:6379
```

Redis can be used for caching and multi-node synchronization. If Redis is not configured, single-node deployments still work, but multi-node deployments must share the same Redis instance.

## Multi-Node Deployment Entry Point

Multi-node deployments require all nodes to share the same database, the same Redis instance, and the same `SESSION_SECRET` / `CRYPTO_SECRET` values. Set the following on slave nodes:

```yaml
environment:
  - NODE_TYPE=slave
  - FRONTEND_BASE_URL=https://your-domain.example.com
```

For a full example, see [Cluster Deployment](/installation/deployment-methods/cluster-deployment).
