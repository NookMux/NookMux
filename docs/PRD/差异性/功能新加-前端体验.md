## Dashboard 流量桑基图四连 `a68041f7d` + `061948011` + `8ad83bf62` + `5e8664464`

涉及文件（整链）：
1. 后端 `controller/usedata.go` + `router/api-router.go`（新增 `/api/data/flow`）→ `internal/controller/usedata.go` + `internal/router/api_router.go`
2. `model/usedata_flow.go`（新）+ `model/usedata.go` + `model/log.go`（QuotaData 加 group/token_id/channel_id 维度）→ `internal/model/`
3. 前端 `dashboard/components/flow/` + `multi-select.tsx` → `web/src/features/dashboard/`

原因：
1. fork dashboard 仅有 overview/models/users 三个 section，无流量桑基图；图表库（@visactor/vchart）与上游一致。四提交为一个功能链：基础图 → 节点上限（防大范围渲染卡死）→ 交互高亮/持久筛选 → 敏感信息脱敏开关。
2. **注意**：需扩展 quota_data 表列（三库迁移），且 fork 有刻意的写入匿名化设计（applyTrackingConfig）——关闭 by_user/by_model 时 flow 维度应同步退化；i18n 按 fork 的 locales/{en,zh}/ 分文件结构。

应当表现为：
1. dashboard 新增 flow section（建议 adminOnly），用户→令牌→模型→渠道流量路径图，节点超限聚合"其他"，头部有脱敏眼睛开关。8ad83bf62 的两个独立子项（筛选弹窗回显、用户分析状态提升）已拆到 [修复](修复.md) 篇「前端修复」节，可先行移植。

## `fc26b88fd` 分组倍率编辑器增强（JSON 静默解析已具备，充值倍率并表 / 特殊分组下拉可移植）

涉及文件：
1. `group-ratio-form.tsx` / `group-ratio-visual-editor.tsx` / `group-special-usable-editor.tsx` → fork 同名三文件（`web/src/features/system-settings/models/`）+ i18n

原因：
1. 上游三项增强中，"解析失败静默回退" fork 已具备：`safeJsonParse`（`web/src/features/system-settings/utils/json-parser.ts`，含 fallback + silent 语义）覆盖了该场景。
2. 剩余差异：①充值倍率（topupGroupRatio）在可视化编辑器中是独立只读单元格列表（`group-ratio-visual-editor.tsx:436-465`），改值需铅笔按钮弹 `SimpleGroupDialog` 或切 JSON 模式，未并入主表格列；②特殊分组规则编辑器已是结构化表单（Select 操作符 + Input，`group-special-usable-editor.tsx:197` 起），但 targetGroup/新分组名字段仍是自由文本，没有已知分组下拉。

应当表现为：
1. 择需移植：特殊分组的分组名字段补已知分组下拉；充值倍率并入可视化主表格列。fork 与上游该组文件结构已大幅分化，不能直接 cherry-pick。

## `928b47507` playground 聊天参数设置面板

## `97bbb7c8c` 定价计算支持按所选分组

涉及文件：
1. `web/src/features/pricing/lib/dynamic-price.ts`（:67-81 取最小分组倍率）
2. `web/src/features/pricing/components/pricing-columns.tsx`、`model-card.tsx`、`index.tsx`

原因：
1. 侧栏分组筛选只过滤模型列表，展示价格仍取最低倍率——用户筛选 vip 分组后看到的仍是最低价，与上游行为不一致。

应当表现为：
1. 价格计算接受 `selectedGroup`，选中具体分组按该分组倍率计算，未选时维持最小倍率。
