## `2f23a6673` SMTP STARTTLS 与 NTLM 认证支持

涉及文件：
1. `common/email.go` → `internal/common/email.go:48-91`（仅 465 隐式 TLS 与 smtp.SendMail 两分支，无显式 STARTTLS/NTLM 控制）
2. `common/email_ntlm_auth.go`（新增）→ `internal/common/`（新建）
3. `common/constants.go` → `internal/common/constants.go:72-74`（增补 STARTTLS/InsecureSkipVerify 变量）
4. 前端 SMTP 设置 + i18n（en/zh 两份）

原因：
1. fork 的 SMTP 仅 465 隐式 TLS（`tls.Dial`，`:49-52` 硬编码 `InsecureSkipVerify: true`）与非 465 的 `smtp.SendMail` 两分支；标准库虽会在服务器宣告时自动协商 STARTTLS，但无显式加密模式控制、无 NTLM，要求显式 STARTTLS/NTLM 的 587 Exchange 场景不可用，且 SMTP 无独立 skip-verify 开关（HTTP 的 `TLS_INSECURE_SKIP_VERIFY` 不接线到 SMTP）。

应当表现为：
1. `newSMTPClient`（SSL/STARTTLS/明文三模式 + 可配置 InsecureSkipVerify）与 `AutoSMTPAuth`（PLAIN 优先、LOGIN 兼容、NTLM 兜底）；前端加密模式选项。

## `70c0b37ee` 移除零引用的 date-fns 直接依赖

涉及文件：
1. `web/package.json`（dependencies 删 `"date-fns": "^4.4.0"`）+ `bun.lock`

原因：
1. fork `web/src` 与 scripts 中 grep date-fns 零命中（日历 locale 走 `react-day-picker/locale`，react-day-picker@10 自带 date-fns 传递依赖），直接依赖纯属冗余。

应当表现为：
1. 删除后 `bun install`、`bun run build`、`bun run typecheck` 通过；`bun pm why date-fns` 仅剩 react-day-picker 传递引用。

## `95e8c5eec` Rsbuild/Tailwind 构建管线优化

涉及文件：
1. `web/rsbuild.config.ts`、`web/postcss.config.mjs`（删除）、`web/package.json`

原因：
1. fork 仍走 `@tailwindcss/postcss` + `web/postcss.config.mjs` 的 PostCSS 管线（`package.json` 中 `@tailwindcss/postcss`/`postcss` 均在）；上游改用 `@rsbuild/plugin-tailwindcss`（Rsbuild 2 官方插件，Lightning CSS 管线）提升构建速度。

应当表现为：
1. Tailwind 编译改走 Rsbuild 插件管线。注意上游同时调整了 buildCache 策略，需结合 fork CI 缓存实测 CSS 产物无陈旧后取舍。
