- 本文档将原本按**时间线**排列的 151 个提交，重新按**功能模块**（二级标题）归类。
- 每个模块内部再按**具体功能**聚合为三级标题：同一功能的实现、后续修复与优化合并在
  同一个三级标题下，按时间先后排列，便于看出该功能的演进过程。
- 三级标题下先给出功能概述，随后逐行列出所属提交，格式为
  `commit hash`-编号：提交标题（编号即原时间线序号，便于交叉核对）。
- 编号规则：首批 119 个提交沿用原编号 **#1～#117**（越新编号越小）；
  2026年8月8日～8月20日新增的 32 个提交使用 **增#1～增#32** 编号（同样越新编号越小，
  增#1 = 8月20日最新），以保持原编号稳定。
- 同一原始条目含多个 hash 时（原序 #46 含 2 个 hash、原序 #56~58 含 4 个 hash），
  在同一行内以 ` / ` 分隔展开列出，提交计数以 hash 为准。
- 各提交的具体日期可在文末「附录：提交完整性核对」表中查询。

## 一、风控中心（封禁与安全防护） — 7 项功能 / 21 个提交

> 该模块是跨时间最长的功能优化之一：从 IP 日志覆盖、IP/IPv6 封禁、自动匹配封禁、批量测活封禁，到连锁封禁、封禁原因展示、风控中心整体优化，逐步构筑了完整的封禁与安全防护体系。
> 8 月增量批次继续深化：IP 封禁独立提示页与批量操作、被封账号追溯、邀请连坐多层查询与默认全量封禁。

### IP 封禁拦截与自动匹配

支持按 IP（含 IPv6 CIDR）封禁并拦截特定请求，自动匹配 IP 触发封禁，同时记录 IP 日志覆盖率。

- 1c81584c-原序#104：风控中心添加IP 日志记录覆盖率
- 91749d35-原序#78：支持封禁ip，拦截特定ip请求
- da82a98a-原序#70：修复 IPv6 CIDR 封禁
- f73da8dc-原序#69：支持自动匹配ip封禁

### 批量封禁与测活封禁

支持批量封禁与自动封禁批量测活（可配置参数），并持续修复封禁问题、优化封禁逻辑和错误处理。

- e4b24491-原序#65：支持批量封禁
- 8c7dfe06-原序#64：支持自动封禁批量测活，可配置参数
- 10da1c0a-原序#61：修复测活封禁机制
- 3f672407 / 2c53b98b-原序#46：修复封禁问题
- 9a6f5c0f-原序#34：风控中心优化封禁

### GitHub 注册时间限制

风控功能：封禁/限制 GitHub 账号注册时间，防止新注册账号滥用。

- a952a8f0-原序#47：支持封禁/限制github注册时间

### 封禁原因展示

- 34656d33-原序#38：已登录的账号支持展示封禁原因

- 8828ba51-原序#9：支持连锁封禁
- 4c73bcde-增#15：添加禁用邀请码用户的处理逻辑
- f63c509a-增#8：支持邀请连坐多层查询
- f5064163-增#7：默认封禁全部邀请关联账号

命中封禁规则时渲染专门提示页面而非 JSON 错误，覆盖后台请求路径并修复与背景请求处理的冲突。
