## Verification Baseline

This page uses the current repository code as the source of truth, and the verification scope is limited to `docs/en/api/`:

- Routing: `internal/httpapi/router/api_router.go`, `internal/httpapi/router/relay_router.go`, `internal/httpapi/router/dashboard.go`
- Request boundaries: `internal/httpapi/controller/` (per-resource subpackages)
- AI request shapes: `internal/domain/shared/`, `internal/relay/`
- Management resource shapes: `internal/model/`, `internal/config/`

The current verification starts with **255** runtime method/path entries; after normalization, the original Chinese generated page covers **180** entries. The mechanical set difference is **99 missing** and **24 stale** entries. Dynamic routes such as `/api/oauth/:provider`, `/v1/models/*path`, and `/v1beta/models/*path` cover multiple concrete URLs, so they cannot be judged by string matching alone.

The generated pages refer to `openapi/generated/**/*.json` and generation scripts that are not present in this repository, so their parameter tables cannot be reconstructed here. This page therefore records the contract confirmed by the current Go code and serves as a project-level override layer for `docs/en/api/`.

## Confirmed Unsupported

The following capabilities are not available in the current project, and the corresponding 22 Chinese API pages have been removed in this round:

- Video jobs: `/v1/videos*`, `/v1/video/generations*`, `/kling/v1/videos*`, `/jimeng/`
- Creem: `POST /api/creem/webhook`, `POST /api/user/creem/pay`
- Legacy ratio endpoints: `GET /api/ratio_config`, `GET /api/ratio_sync/channels`, `POST /api/ratio_sync/fetch`
- Legacy security status: `GET /api/verify/status`
- Unregistered OAuth providers: Discord, OIDC, Telegram, WeChat

Current OAuth only registers `github` and `linuxdo`. Any other provider that reaches `GET /api/oauth/:provider` still returns "Unknown provider"; that does not make it a supported capability.

## Runtime Routes Missing from the Original Generated Page

The following routes are registered in code but had no corresponding contract in the original generated page.

### System, Users, and Auth

```text
GET    /api/rankings
GET    /api/user/checkin
POST   /api/user/checkin
GET    /api/user/self/usage_log_fields
PUT    /api/user/passkey/:id
DELETE /api/user/passkey/:id
POST   /api/user/epay/notify
GET    /api/oauth/:provider
POST   /api/oauth/email/bind
```

- `GET /api/rankings`: optional `period` query, defaulting to `week`.
- `GET /api/user/checkin`: optional `month` query in `YYYY-MM` format.
- `PUT /api/user/passkey/:id`: JSON body `{ "device_name": "..." }`.
- `POST /api/oauth/email/bind`: JSON body must include `email` and `code`.
- OAuth callbacks must include both the `state` issued in the session and the `code` returned by the provider.

### Root System Settings

```text
GET    /api/option/value
GET    /api/option/json_map
PUT    /api/option/json_map
DELETE /api/option/json_map
GET    /api/option/json_array
PUT    /api/option/json_array
DELETE /api/option/json_array
GET    /api/option/channel_affinity_cache
DELETE /api/option/channel_affinity_cache
POST   /api/option/reset_tool_billing_rules
```

- `option/value`: the `key` query parameter is required, and sensitive configuration cannot be read.
- `option/json_map` query parameters: `key`, `page`, `page_size`, `keyword`.
- JSON Map write body: `key`, `map_key`, `old_map_key`, `value`; delete body: `key`, `map_key`.
- `option/json_array` keeps only legacy read compatibility for `minimax.voice_whitelist`; `PUT` and `DELETE` explicitly return "migrated to voice management" and can no longer be used as successful write APIs.
- Clearing the affinity cache requires `all=true` or a `rule_name`.

### Database Migration and Performance

```text
GET    /api/db/pre_migrate/info
POST   /api/db/pre_migrate
GET    /api/db/pre_migrate/:id
GET    /api/db/same_type_migrate/info
POST   /api/db/same_type_migrate
GET    /api/db/same_type_migrate/:id
GET    /api/performance/stats
DELETE /api/performance/disk_cache
POST   /api/performance/reset_stats
POST   /api/performance/gc
```

Both migration start endpoints use the same JSON body:

```json
{
  "target_dsn": "target business DB DSN",
  "target_log_dsn": "target log DB DSN",
  "include_logs": true,
  "force": false
}
```

Migration endpoints all require Root privileges; the `job_id` in the response is used to query `/:id`. DSNs are sensitive information, so do not log them or expose them in examples.

### Channel Extensions

```text
POST   /api/channel/test_proxy
POST   /api/channel/ollama/pull
POST   /api/channel/ollama/pull/stream
DELETE /api/channel/ollama/delete
GET    /api/channel/ollama/version/:id
GET    /api/channel/plan/quota/:id
GET    /api/channel/plan/glm/usage/:id
GET    /api/channel/plan/glm/risk/:id
```

- Proxy test body: `{ "proxy": "http://host:port" }`; supports `http`, `https`, `socks5`, and `socks5h`.
- Ollama pull and delete bodies: `channel_id`, `model_name`; streaming pull returns SSE.
- GLM usage query: `type` (default `model`), `startTime`, `endTime`; time format `YYYY-MM-DD HH:mm:ss`, and the range cannot exceed 31 days.

### Token Keys

```text
POST /api/token/batch/keys
POST /api/token/:id/key
PUT  /api/token/:id/key
```

- Batch read body: `{ "ids": [1, 2] }`.
- List, search, and detail endpoints only return a same-length asterisk mask; the full key can only be read through the dedicated endpoints above.
- `PUT /api/token/:id/key` generates a new key and immediately invalidates the old one.

### Tickets

```text
GET  /api/ticket/
GET  /api/ticket/admin
POST /api/ticket/
GET  /api/ticket/:id
POST /api/ticket/:id/reply
POST /api/ticket/:id/close
POST /api/ticket/:id/status
```

- List query: `p`, `page_size`, `status` (default `all`), `keyword`.
- Create body: `title`, `type`, `content`.
- Reply body: `content`; status update body: `status`.
- The route group requires User authentication; the admin list and status operations still validate roles in the business layer.

### Usage Logs and Audit Logs

```text
GET    /api/log/
DELETE /api/log/
GET    /api/log/self
GET    /api/log/stat
GET    /api/log/self/stat
GET    /api/log/token
GET    /api/log/token/usage_log_fields
GET    /api/log/channel_affinity_usage_cache
GET    /api/audit/
GET    /api/audit/modules
```

Common usage-log filters are `p`, `page_size`, `type`, `start_timestamp`, `end_timestamp`, `token_name`, `model_name`, `group`, `request_id`, `upstream_request_id`, `ip`, `ua`, `x_title`, and `http_referer`; admin endpoints also support `username` and `channel`. Normal users cannot use hidden fields as a side channel for filtering.

Audit-log query parameters are `p`, `page_size` (max 100), `username`, `module`, `action_type`, `start_timestamp`, and `end_timestamp`.

### Data Dashboard

```text
GET  /api/data/users
GET  /api/data/media_convert_stats
GET  /api/data/self/media_convert_stats
POST /api/data/recalculate
GET  /api/dashboard/config
PUT  /api/dashboard/config
POST /api/dashboard/config/reset
```

- Data endpoints use `start_timestamp` and `end_timestamp`; recalculation requires both values to be positive and `end_timestamp > start_timestamp`.
- Dashboard updates use a JSON map from field name to value. Writable fields include panel switches, aggregation switches, refresh interval, time range, and ranking limit; field names follow the JSON names in `DashboardConfig`.

### Stored Media

```text
GET    /api/stored_media/
GET    /api/stored_media/self
GET    /api/stored_media/:media_type/:id
DELETE /api/stored_media/:media_type/:id
POST   /api/stored_media/batch
```

- List query: `p`, `page_size`, `start_timestamp`, `end_timestamp`.
- `media_type` can only be `image` or `video`.
- Batch delete body: `{ "items": [{ "id": "...", "media_type": "image" }] }`.
- The returned `/mcp/image/:id` and `/mcp/video/:id` URLs already include `exp` and `sig`, are valid for one hour, and are not public file APIs that you can assemble yourself.

### Dynamic Ratio

```text
GET    /api/dynamic_ratio/status
GET    /api/dynamic_ratio/rules
POST   /api/dynamic_ratio/rules
PUT    /api/dynamic_ratio/rules
DELETE /api/dynamic_ratio/rules/:id
PUT    /api/dynamic_ratio/rules/reorder
PUT    /api/dynamic_ratio/enabled
```

Rule body fields: `id` (required on update), `enable`, `group`, `models`, `concurrency`, `weekdays`, `start_time`, `end_time`, `ratio`, and `priority`. `models` and `weekdays` are JSON array strings, and the time format is `HH:MM`. The reorder body is `{ "ids": [...] }`, and the switch body is `{ "enabled": true }`. The user status endpoint optionally accepts `group`.

### Custom Voice and Voice Management

```text
GET    /api/custom_voice/tags
POST   /api/custom_voice/preview
POST   /api/custom_voice/confirm_quote
POST   /api/custom_voice/confirm
GET    /api/custom_voice/voices/
POST   /api/custom_voice/voices/
PUT    /api/custom_voice/voices/:id
DELETE /api/custom_voice/voices/:id
```

- Preview uses `multipart/form-data` with `file`, `model`, `voice_id`, `text`, `need_noise_reduction`, and `need_volume_normalization`.
- Quote and confirm bodies: `{ "voice_id": "..." }`.
- Voice list query: `page`, `page_size`, `type`, `operator_id`, `voice_id`, `start_timestamp`, `end_timestamp`.
- Voice create/update body: `voice_id`, `type`, `redirect_id`, `allowed`, `remark`; `type` only allows `preview` and `created`.

### AI, Compatibility, and Internal Routes

```text
GET    /v1/models/:model
GET    /v1beta/openai/models
POST   /v1/responses/compact
POST   /v1/edits
POST   /v1/images/variations
DELETE /v1/models/:model
POST   /v1/models/*path
POST   /v1beta/models/*path
GET    /dashboard/billing/subscription
GET    /dashboard/billing/usage
GET    /v1/dashboard/billing/subscription
GET    /v1/dashboard/billing/usage
POST   /pg/chat/completions
GET    /mcp/image/:id
GET    /mcp/video/:id
```

- `GET /v1/models/:model` fetches a single model; `/v1beta/openai/models` is the Gemini OpenAI-compatible model list.
- Responses compact body: `model`, `input`, `instructions`, `previous_response_id`.
- `/v1/edits` is the image-editing compatibility entry.
- `/v1/images/variations` and `DELETE /v1/models/:model` currently return "not implemented" explicitly.
- The two `*path` routes are Gemini dynamic action routes, with actual URLs such as `/v1beta/models/{model}:generateContent`.
- `/pg/chat/completions` uses the user session and serves the built-in Playground; it does not use API tokens.
- Billing routes use read-only API tokens, and their responses are compatible with the legacy OpenAI Dashboard format.

## Existing API Parameter Changes

| Interface | Current contract change |
| --- | --- |
| `GET /api/user/search` | In addition to the compatible `keyword` and `group` fields, it now accepts `username`, `display_name`, `email`, `linux_do_id`, `github_id`, `status`, `role`, `p`, and `page_size`. |
| `PUT /api/user/setting` | The current fields are `notify_type`, `quota_warning_threshold`, `webhook_url`, `webhook_secret`, `notification_email`, `bark_url`, `gotify_url`, `gotify_token`, and `gotify_priority`. |
| `GET /api/channel/` | Adds `group` filtering; `p`, `page_size`, `id_sort`, `tag_mode`, `status`, and `type` remain supported. |
| `GET /api/channel/search` | In addition to `keyword`, `group`, and `model`, it now accepts `id`, `name`, `tag`, `status`, `type`, `id_sort`, `tag_mode`, `p`, and `page_size`. |
| `POST/PUT /api/token/` | Adds `quota_type`, `window_hours`, `window_quota`, `window_start_hour`, `cycle_days`, and `cycle_quota`; runtime statistics fields cannot be set by clients. |
| `GET /api/token/search` | Adds `token`, `group`, `status`, `all`, `p`, and `page_size`; `status` uses 1 for enabled, 2 for disabled, 3 for expired, and 4 for quota exhausted. |
| `POST/PUT /api/models/` | Adds nullable `context_length`, `max_output_tokens`, `input_modalities`, `output_modalities`, `capabilities`, `knowledge_cutoff`, `release_date`, and `parameter_count`; `sync_official` is no longer a JSON API field. |
| `POST/PUT /api/vendors/` | Adds nullable `data_retention_days` and `training_opt_out`. |
| `POST /v1/chat/completions` | The current DTO also accepts `verbosity`, `top_k`, `parallel_tool_calls`, `safety_identifier`, `store`, `prompt_cache_key`, `prompt_cache_retention`, `metadata`, `prediction`, and several vendor-specific extension fields. |
| `POST /v1/responses` | Adds `include`, `metadata`, `parallel_tool_calls`, `top_logprobs`, `safety_identifier`, `service_tier`, `store`, `prompt_cache_key`, `prompt_cache_retention`, `text`, `user`, `max_tool_calls`, `prompt`, and other fields; `instructions` accepts raw JSON rather than only strings. |
| `POST /v1/messages` | Adds Claude fields such as `context_management`, `output_config`, `output_format`, `container`, `mcp_servers`, and `service_tier`. |
| `POST /v1beta/models/{model}:generateContent` | The current request also supports `safetySettings`, `tools`, `toolConfig`, `systemInstruction`, `cachedContent`, and `requests` for batch requests. |
| `POST /v1/embeddings` | In addition to the standard fields, the current DTO also accepts `user`, `seed`, `temperature`, `top_p`, `frequency_penalty`, and `presence_penalty`. |
| `POST /v1/rerank` | Adds `max_chunk_per_doc` and `overlap_tokens`. |
| `POST /v1/audio/speech` | Adds `instructions`, `stream_format`, and `metadata`. |
| `POST /v1/images/generations` | The current request uses direct OpenAI-style fields such as `model`, `prompt`, `n`, `size`, `quality`, and `response_format`; it no longer uses the old `input` + `parameters` wrapper from the previous docs. |

Whether AI extension fields are forwarded still depends on the target channel and parameter filtering configuration; "DTO can parse it" does not mean every upstream supports it.

## Authentication Changes

- `GET /api/models` requires User authentication.
- `GET /api/channel/fetch_models/:id` and `POST /api/channel/fetch_models` require Root authentication.
- `/api/option/*`, `/api/db/*`, and `/api/performance/*` all require Root authentication.
- Token list and detail endpoints no longer return plaintext keys; reading and resetting keys must use dedicated endpoints.
- `GET /api/pricing` and `GET /api/rankings` are controlled by the corresponding Header Nav module switches.
